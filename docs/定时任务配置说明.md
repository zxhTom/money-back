# 定时任务配置说明（仅配置与表数据，不改业务代码）

开发一个定时任务时，需要满足以下配置并在指定表里添加数据。

---

## 一、需要具备的前置条件（代码侧）

- 已有一个实现 `JobHandler` 接口的 Spring Bean，且 **Bean 名称** 与下面要填的 `handler_name` **完全一致**（如 `contractOverdueCheckJob`）。
- 若没有该 Bean，定时任务在「同步」或「启用」时会报“处理器不存在”等错误。

---

## 二、需要写入数据的表（仅 1 张业务表）

**只需在业务库中维护一张表：`infra_job`。**

Quartz 运行时用的表（`QRTZ_JOB_DETAILS`、`QRTZ_TRIGGERS`、`QRTZ_CRON_TRIGGERS` 等）**不要手动插数据**，由应用在「同步」或「创建任务」时自动写入。

---

## 三、`infra_job` 表结构及字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | bigint | 否（自增） | 任务编号，MySQL 自增可不写 |
| `name` | varchar(32) | 是 | 任务名称（界面显示） |
| `status` | tinyint | 是 | 0=初始化中，1=正常(启用)，2=暂停 |
| `handler_name` | varchar(64) | 是 | **处理器的名字，必须与 JobHandler 的 Spring Bean 名称一致** |
| `handler_param` | varchar(255) | 否 | 处理器的参数，无则 `''` 或 NULL |
| `cron_expression` | varchar(32) | 是 | CRON 表达式，如 `'0 0 0 * * ?'` 每天凌晨 |
| `retry_count` | int | 是 | 重试次数，不重试填 0 |
| `retry_interval` | int | 是 | 重试间隔(毫秒)，无则 0 |
| `monitor_timeout` | int | 是 | 监控超时(毫秒)，不监控填 0 |
| `creator` | varchar(64) | 否 | 创建者，如 `'1'` |
| `create_time` | datetime | 是 | 创建时间 |
| `updater` | varchar(64) | 否 | 更新者 |
| `update_time` | datetime | 是 | 更新时间 |
| `deleted` | bit(1) | 是 | 是否删除，未删除为 `b'0'` |

---

## 四、示例：新增「合同逾期检查」任务（SQL 插入）

```sql
INSERT INTO `infra_job` (
  `name`, `status`, `handler_name`, `handler_param`,
  `cron_expression`, `retry_count`, `retry_interval`, `monitor_timeout`,
  `creator`, `create_time`, `updater`, `update_time`, `deleted`
) VALUES (
  '合同逾期检查 Job',           -- name
  1,                            -- status: 1=正常启用（2=暂停则不会跑）
  'contractOverdueCheckJob',    -- handler_name：与 Bean 名一致
  '',                           -- handler_param
  '0 0 0 * * ?',                -- cron: 每天 0 点
  3, 0, 0,                      -- retry_count, retry_interval, monitor_timeout
  '1', NOW(), '1', NOW(), b'0'  -- 审计字段 + deleted
);
```

## 五、插入 `infra_job` 之后必须做的操作：触发同步

仅插入 `infra_job` 后，Quartz 里还没有对应的 Job 和 Trigger，需要调用后端**同步接口**，把 `infra_job` 的数据同步到 Quartz（`QRTZ_JOB_DETAILS`、`QRTZ_TRIGGERS`、`QRTZ_CRON_TRIGGERS`）。**不要**在 QRTZ_* 表里手写数据。

### 方式一：页面上有「同步」按钮时

1. 登录管理后台  
2. 打开 **基础设施 → 定时任务**  
3. 点击 **「同步」** 按钮  

### 方式二：页面上没有「同步」按钮时（直接调接口）

当前项目的前端可能没有暴露「同步」按钮，可以直接调用后端接口触发同步：

- **接口**：`POST /admin-api/infra/job/sync`
- **权限**：需要已登录且拥有 `infra:job:create` 权限
- **请求头**：`Authorization: Bearer <登录后的 token>`，若多租户需加 `tenant-id: <租户ID>`
- **请求体**：无（空 body 即可）

**示例（curl，请把 `<BASE_URL>`、`<TOKEN>`、`<TENANT_ID>` 换成实际值）：**

```bash
curl -X POST '<BASE_URL>/admin-api/infra/job/sync' \
  -H 'Content-Type: application/json' \
  -H 'Authorization: Bearer <TOKEN>' \
  -H 'tenant-id: <TENANT_ID>'
```

- `<BASE_URL>`：如 `http://localhost:48080`  
- `<TOKEN>`：登录管理后台后拿到的 accessToken（浏览器开发者工具 → 接口请求头里可看到）  
- `<TENANT_ID>`：你的租户 ID，单租户一般是 1，可从登录接口响应或请求头里看  

调用成功（HTTP 200）后，所有在 `infra_job` 中的任务会被同步到 Quartz，包括新加的「合同逾期检查」等。

---

## 六、小结

| 项目 | 说明 |
|------|------|
| **需要加数据的表** | 只有 **`infra_job`** |
| **QRTZ_* 表** | 不手写，由应用在「同步」或「创建任务」时维护 |
| **关键配置** | `handler_name` 必须与 JobHandler 的 Bean 名称一致；`status=1` 才会被调度 |
| **插入后必做** | 调用 **POST /admin-api/infra/job/sync**（或使用页面「同步」按钮） |

若之前出现过“触发器引用的 Job 不存在”的报错，需先执行清理脚本 `sql/mysql/quartz_fix_contract_overdue_trigger.sql` 删除孤立触发器，再执行上述同步。
