# 时间窗口管理 - 业务规则

## 1. 用户集合规则

- **选定用户集合**：从系统用户列表中多选，保存为 ID 列表（如 `selectedUserIds`）。
- **排除用户集合**：从系统用户列表中多选，保存为 ID 列表（如 `excludedUserIds`）。
- **合并规则**：若某用户同时出现在「选定」和「排除」中，**以排除为准**，即该用户不计入有效用户。
  - 有效用户 = 选定用户集合 − 排除用户集合（集合差）。
  - 后端在使用「有效用户」时（如推送、统计）应按此规则计算，存储仍保留选定、排除两个独立列表。

## 2. 快捷选择（前端为主）

- 仅用于快速填充「结束时间」：
  - **1**：结束时间 = 开始时间 + 1 小时
  - **3**：结束时间 = 开始时间 + 3 小时
  - **7**：结束时间 = 开始时间 + 7 小时
- 「开始时间」可为用户选择的时间，或「当前时间」。
- 后端可选择性存储 `quickSelect`（1/3/7）用于列表展示或统计，非必填。

## 3. 激活状态

- 新增记录**默认激活**（如 `status = 1` 或 `active = true`，以实际字段为准）。
- 仅**激活状态**下的时间窗口参与「时间窗口重合校验」；未激活记录不参与校验。

## 4. 时间窗口重合校验

### 4.1 适用场景

- 在**新增**或**修改**一条时间窗口记录时执行。
- 修改时：与「当前记录」时间窗口重合不视为冲突，即校验时需**排除当前记录 ID**。

### 4.2 重合定义

- 两个区间 `[start1, end1]` 与 `[start2, end2]` 有交集即视为重合。
- 重合时长 = `min(end1, end2) − max(start1, start2)`（单位与配置一致，一般为小时）。

### 4.3 阈值规则（默认 1 小时，可配置）

- 设配置的「允许的最大重合时长」为 **T**（单位：小时，默认 T = 1）：
  - **重合时长 > T**：**不允许**保存，返回错误，前端禁止提交。
  - **0 < 重合时长 ≤ T**：**允许**保存，但需**警告**用户（前端弹窗确认后仍可提交）。
  - **重合时长 = 0**（即不重合）：允许保存，无需警告。

### 4.4 校验范围

- 只与**当前已存在的、激活状态的**时间窗口做重合判断。
- 若存在多条重合，取**最大重合时长**与 T 比较；或按业务需要取「是否存在任一条 > T」决定是否禁止。

### 4.5 配置

- **T（小时）** 需支持配置（如系统参数表、配置中心、或独立配置接口）。
- 前端通过接口获取 T（例如在「重合校验」接口响应中返回 `overlapThresholdHours`，或单独配置接口），用于展示与交互。

## 5. 与前端交互小结

- 前端在提交前会调用「重合校验」接口；后端应返回：是否允许、重合时长、阈值、提示文案。
- 后端在 **create/update** 时建议再次做相同规则的重合校验，并返回明确错误信息，保证数据一致性。
