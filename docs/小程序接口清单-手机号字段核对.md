# 小程序接口清单（供后端核对手机号相关字段）

**文档用途**：罗列当前微信小程序客户端实际调用的后端接口，并标注**是否涉及手机号**（请求体/Query、响应中被前端使用的字段，或用户可填写的联系方式），便于后端排查日志、脱敏、权限与 DTO 返回范围。

**基址说明**：业务请求经 `utils/request.js` 拼接为 `info.js` 中 `baseUrls` 对应环境地址（如 `…/admin-api`）+ 下表路径。除上传外，请求体会自动附带 `appId`、`appVersion`（与手机号无关）。

**「是否涉及手机号」列约定**

- **是**：前端明确发送或消费 `phone` / `mobile`，或提交字段（如 `contactInfo`）语义上允许用户填写手机号。
- **否**：当前仓库代码未对上述字段做组装或展示；若接口响应 DTO 仍包含手机号，需后端结合接口契约与日志单独审计。
- **视情况**：仅当特定调用路径传入含手机号的参数时才会涉及；主流程可能未使用。

**「响应是否含手机号字段」列约定**

- **是**：根据当前仓库后端 Controller/VO，成功响应的 JSON 中会出现结构化字段 `mobile`（或嵌套 `AdminUserDO` 等含 `mobile`）。
- **否**：返回类型中无上述字段（或仅为 `Boolean`/`Long`/业务 VO 无手机）。
- **待核对**：本仓库未找到对应路径实现，或响应为第三方 Map/动态结构，需联调或抓包确认。

**如何对比「小程序不需要手机号但接口仍返回手机号」**：看同一行若 **是否涉及手机号** 为 **否**（或 **视情况** 且实际未传手机），而 **响应是否含手机号字段** 为 **是**，即属于可优先做响应裁剪、脱敏或换用精简 DTO 的场景。

---

## 核对总结（便于快速对照）

- **前端明确用机号（是）**：手机验证码/密码登录、个人资料拉取与保存、注册（主包）、意见反馈联系方式等；这些与「响应是否含手机号」多为一致需求，重点在日志与存储合规。
- **前端未用机号（否）但本仓库响应仍带 `mobile` 的接口**（重点差异）：
  - `**POST /system/auth/login`**：`AdminAuthServiceImpl.login` 在 `AuthLoginRespVO` 上 `**setUser(user)**`，返回完整 `AdminUserDO`，含 `mobile`。小程序侧若仅账号密码登录且不读 `user.mobile`，仍会在响应里拿到手机号。
  - `**POST /wechat/login**`：包装为 `WechatLoginResponse`，内含 `**AdminUserDO user**`（含 `mobile`）。文档中前端列为「否」是指请求只带 `code`，但响应仍会带出用户对象（含手机）。
- **其余合同/订单/支付/征信相关接口**：本仓库对应 VO（如 `ContractRespVO`、`ContractDO`、`PayOrderRespVO`、`PayOrderVO`、`RecentContractVO` 等）**未声明 `mobile` 字段**，标为 **否**。若生产环境另有字段扩展或联表透出，需以实际抓包为准。
- `**/auth/login-by-code`、`/auth/login-by-phone`、`/verify-captcha`、`POST /system/login`、反馈列表 FAQ 等**：本仓库 **未找到** 同名 Controller 或路径与文档不完全一致，响应列标 **待核对**。

## 建议后端重点核对项

1. `**GET /system/user/profile/get`**：前端展示与缓存 `mobile`，需关注日志、监控、第三方转发是否脱敏。
2. `**PUT /system/user/profile/update**`：会回写 `mobile`，需与注册/账号体系字段策略一致。
3. `**POST /auth/login-by-code`、`POST /auth/login-by-phone**`：请求含明文 `phone`，注意访问日志与限流风控。
4. `**POST /custom/contract/dashboard/register**`：主包注册路径上传 `mobile`。
5. `**POST /system/feedback/submit**`：`contactInfo` 可能含手机号，存储与工单展示需合规处理。
6. **合同/订单类 GET**：表中标为「否」仅表示前端**未在代码中解构手机号**；若响应体仍包含当事人联系方式，请按业务决定是否在小程序场景裁剪字段。
7. `**POST /system/auth/login` 与 `POST /wechat/login`**：小程序文档中「是否涉及手机号」为否，但当前后端响应仍可能携带完整 `AdminUserDO`（含 `mobile`）。若产品要求小程序链路最小化暴露，可改为精简用户 DTO 或登录响应不附带 `user` 全量。
